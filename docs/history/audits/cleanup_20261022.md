# Cleanup completed — October 22, 2026

The maintained checkout now separates shared implementation, experiment recipes, saved evidence and historical context. This implements the [approved proposal](CODEBASE_CLEANUP_PLAN.md), including one directory per experiment family. The current research root is on the local `cleanup/experiment-layout` branch; the preserved `../code/GeoAE` checkout remains clean at `1121151`.

The [architecture guide](../../architecture.md), [usage guide](../../usage.md) and [21-family experiment index](../../../experiments/README.md) replace the old scattered starting points. The `geoae` dispatcher exposes 113 commands through readable groups, while all seven previously installed console commands remain available. Prior `python -m` module paths have a [relocation ledger](source_paths.json); callers should use the canonical modules or dispatcher. There is no duplicate compatibility implementation for every old module name.

The six main paper recipes are `llama.yaml`, `llama_no_bypass.yaml`, `gemma.yaml`, `gemma_no_bypass.yaml`, `qwen.yaml` and `qwen_no_bypass.yaml`. Each other recipe has one editable owner. All 206 recorded old/intermediate configuration aliases resolve, and all 198 current YAML recipes load. Similar-looking 10M and matched-depth train10M datasets remain distinct. Duplicate consolidation requires equality of the entire effective configuration, including defaults; [the receipt](config_consolidation.json) records those checks.

## What was removed or consolidated

Executable code hidden in `eval_out/` and `logs/` now lives in shared packages or experiment-specific folders. Cluster and campaign scripts moved with their experiment owners. Eleven historical source patch/repair tools were retired from the maintained tree and preserved, byte-for-byte, in the external cleanup archive. The remaining compatibility adapter is available explicitly for historical snapshots; new evaluation snapshots use the reconciled source directly.

Repeated configuration comment blocks were compacted in 161 recipes, removing 8,283 lines while preserving their parsed values. Six no-Sinkhorn variants now encode the flag previously stated only in recipe comments. Their behavior is recorded in YAML, checkpoints and resume validation. The [comment/flag receipt](config_cleanup.json), [original configuration ledger](../../../experiments/config_migration.json) and [consolidation receipt](config_consolidation.json) distinguish these stages.

Demonstrated implementation duplication was reduced through shared extraction helpers, one balanced-centroid update implementation, common workflow/source-snapshot helpers, and one Qwen/generic nonlinear evaluation planner. Tokenizer authentication happens at loading rather than package import. Scientific protocol variants remain separate where their pooling, initialization, document selection, normalization, decoder or intervention semantics differ.

Generated caches, bytecode, build directories and editable-install metadata are ignored and can be regenerated. Saved datasets, run receipts, logs, reports and source archives were moved out of the code tree rather than deleted. The [artifact catalog](../../artifacts.json) locates the 2,071 preserved files and their hashes. Small result-reference manifests remain with the nonlinear experiment family. Historical guides, reports, notes and migration records moved under `docs/history/`; current documentation has a shorter reading path.

## Functionality and integrity

The starting research root and older checkout contained different capabilities. Reconciliation retained newer nonlinear decoder/checkpoint/intervention behavior and restored older matched-SAE, control, baseline and campaign functionality. A final symbol audit of 124 non-pinned package modules found all 725 public functions, 54 public classes and 118 public methods from the preserved checkout available in their mapped modules or shared reexports. Existing positional model arguments remain stable; added options are optional. This is evidence of API coverage, not a claim that every cluster workload was executed.

Targeted correctness fixes made during cleanup include forwarding configured geometry settings in both KL trainers, allowing disabled centroid reinitialization, persisting assignment mode, retaining effective pipeline overrides, and portable scratch allocation with capacity/headroom checks. Parity tests compare shared balanced updates, initialization, RNG state, metadata and checkpoint/resume behavior.

Read-only artifact lookup and working/output resolution are separate. A relative output path cannot silently redirect a writer into the preserved artifact store. Analysis/report tools read archived inputs explicitly and write new local outputs. Nonlinear comparison analysis reproduces all three saved CSV tables byte-for-byte; the summary JSON matches except for its relocated paper-source path.

New evaluation preparation verifies frozen training core identities before creating a snapshot and after copying. New snapshots contain the configuration alias map, pinned SAE receipt, generic configs, scheduler/HTML templates and paper styles; their runtime resources participate in source identity checks. Historical manifests retain their original hash schema and recorded launcher paths. Incompatible historical `--paper-repo` layouts fail before creating output; a complete external reconciled checkout remains supported. Existing frozen snapshots and recovery state were not rewritten.

## Remaining evidence limitations

Width/report panel inputs and selected older campaign manifests are similarly documented in their family READMEs. The paper's [dependency record](../../paper/dependencies.json) distinguishes authoring inputs from scientific evidence.

A direct read-only Delta lookup could not authenticate in batch mode, so candidate remote table-input locations remain unverified. No GPU jobs, model loads, activation extraction, paid judge calls, remote file changes or replacement experiments were performed. Existing remote storage paths and frozen evidence retain their meaning.
